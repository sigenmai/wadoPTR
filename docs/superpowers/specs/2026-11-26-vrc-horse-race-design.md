# 荒野横断ホースレース（仮題）設計書

日付: 2026-11-26
対象: VRChat ワールド（VRChat SDK3 Worlds + UdonSharp / Unity）

## 1. 何を作るか・なぜ作るか

馬に乗って荒野と砂漠を駆け抜け、**能力で互いを妨害し合う** VRChat 用マルチプレイのレースワールド。
『ジョジョの奇妙な冒険 第7部』の「大陸横断レース × 特殊能力 × 遺物の奪い合い」というワクワク感に刺激を受けているが、
**作品名・キャラクター・スタンド名・デザイン・セリフ等は一切使わない完全オリジナル**として作る。

最優先は **馬の操作感**。妨害バトルがあっても、乗っていて気持ちいいことが土台。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
- VR・デスクトップ両方のプレイヤーが同じ条件で遊べる
- 1回のプレイ：**3ステージ × 約5分 = 約15分**、**最大8人**
- 固定能力（レース前に1つ選択）＋ コース上の **遺物** で能力が強化される
- 高低差のある地形（峡谷・崖・砂丘）を走ること自体が楽しい
- トゥーン調のビジュアル

### 非ゴール（今回はやらない）
- 原作の名前・キャラ・能力・見た目の再現
- セーブ / ランキングの永続化
- NPC（AI）ライダー
- 能力4種を超える拡張、アバターのカスタマイズ

### アンチゴール（動いても失敗とみなすもの）
- VR で酔う（急なカメラ回転・揺れ・強制的な視点移動）
- 他プレイヤーの馬がガクガク・ワープして見える
- VR とデスクトップのどちらかが明確に有利
- 妨害が強すぎて操作の上手さが意味をなさない

## 3. 制約
- VRChat SDK3 Worlds + UdonSharp。Udon の制約（同期変数の帯域、Udon の実行速度）に収める
- 組み立て・動作確認はユーザーの PC（Unity + VRChat クライアント）で行う。Claude はスクリプトと設計・手順書を書く
- **対応プラットフォームは PC のみ**（PC VR ＋ デスクトップ）。Quest/Android 対応はしない
- ワールドが重くなりすぎないこと（トゥーン調を選んだ理由の一つ）
- **地形・コースも Claude が作る**。Claude はこの環境で Unity を実行できないため、Unity エディタ拡張（メニュー1つでシーンを組み上げるツール）として納品する：
  - 地形生成ツール：ステージごとのパラメータ（峡谷・崖・砂丘・メサ）から Terrain の高さとテクスチャを手続き的に生成
  - コース生成ツール：コースの道筋（スプラインの点列）を定義データとして持ち、チェックポイント・遺物スポーン・スタート/ゴール・コース外リセット領域を自動配置
  - シーン組み立てツール：上記＋ロビー・レース管理・馬プレハブをまとめて配置
- ユーザーの作業は「プロジェクト準備 → メニュー実行 → VRChat でテスト → 感想を伝える」までに絞る。手順書はクリック単位で書く

## 4. 検討したアプローチ

| 案 | 内容 | 判断 |
|---|---|---|
| **A. 自前の馬コントローラー** | プレイヤーは VRCStation で馬に座る。移動はスクリプトで計算（レイキャストで接地・坂沿い、加速・旋回・ジャンプを自前実装）。各自の馬はオーナーがローカルで動かし、位置を同期して他者側で補間 | **採用**。操作感を完全に握れる唯一の方法。VR/デスクトップで挙動を共通化しやすい |
| B. Rigidbody 物理 | 物理演算で馬を動かす | 不採用。挙動がブレやすく調整しにくい、同期でガタつきやすい |
| C. アバター歩行＋見た目だけ馬 | 移動速度を上げるだけ | 不採用。乗っている感覚がなく、操作感重視に反する |

ユーザーが **A** を選択。

## 5. 決まっている設計

### 5.1 馬の操作
挙動（速度・加速・旋回・ジャンプ・スタミナ）は**全プレイヤー共通**。入力だけが違う。

| 操作 | デスクトップ | VR |
|---|---|---|
| 前進 / 減速 | W / S（またはスティック） | 左スティック前後（補助）＋ 手綱を引くと減速 |
| 旋回 | A / D | 手綱の左右どちらかを引く（スティックでも可） |
| 疾走（スタミナ消費） | Shift | 両手で手綱を振る（または指定ボタン） |
| ジャンプ | Space | ボタン |
| 能力発動 | E（照準は視線方向） | トリガー（照準は手の向き） |

- 速度段階：常歩 → 速歩 → 駆歩 → 疾走（スタミナ消費、尽きると一時的に駆歩上限）
- 坂：上りで減速・下りで加速。急な崖は落下、着地時に硬直（高さに応じて）
- **酔い対策（必須）**：カメラは馬の上下動・ピッチをそのまま伝えず平滑化。旋回は滑らか。被弾時に視点を強制回転させない

### 5.2 能力（初期4種、すべてオリジナル）
各能力は **Lv1〜3**。遺物を拾うとLvが上がる（ステージ開始時にLv1へリセット）。

| 能力 | 効果 | 強化で変わるもの |
|---|---|---|
| **砂塵（すなけむり）** | 自分の後方に砂煙を残す。中を通った相手は視界がかすみ、少し減速 | 範囲・持続時間 |
| **投げ縄** | 前方の相手に縄を掛け、自分は引き寄せられて加速、相手は一瞬減速 | 射程・引き寄せ力 |
| **岩壁** | 前方の地面から岩壁をせり上げる（コース妨害） | 壁の幅・枚数 |
| **蜃気楼** | 自分の分身を出し、一定時間半透明化して投げ縄などの対象にならない | 分身数・持続時間 |

- クールダウン制（目安 15〜25秒、調整対象）
- 当たり判定は**発動した側のクライアントで行い**、効果をネットワークイベントで全員へ送る

### 5.3 遺物
- 各ステージのコース上に数か所出現。拾うと能力Lv +1（最大3）
- 取り合いを生むため、一度拾われたらそのステージ中は消える

### 5.4 レース進行
- ロビー：能力選択 → 全員準備完了 or マスターが開始
- ステージ1 → 2 → 3（各約5分）。各ステージの順位でポイント付与、合計で総合優勝
- ステージ間は次ステージのスタート地点へテレポート
- **ステージ終了条件（Claudeの判断）**：1位がゴールしてから60秒、または開始から5分30秒の早いほうで終了。未完走者は通過チェックポイント数（同数なら次CPまでの距離）で順位を決め、完走者より下位としてポイントを付与
- **ステージの広さ（Claudeの判断）**：各ステージは約1km四方のTerrainに収め、曲がりくねったコース（約2.5km）で約5分になるよう速度を調整する。3ステージは同じワールド内で原点近くに並べ、浮動小数点の誤差による揺れを避ける
- **途中参加**：次のステージから参加可（総合ポイントは0から）
- **途中離脱**：その時点のポイントで集計から外す
- 進行管理（ステージ状態・順位・ポイント）はインスタンスマスターがオーナーとして保持し同期

### 5.5 舞台（トゥーン調）
- ステージ1：**荒野** — 峡谷、岩橋、崖下りのショートカット
- ステージ2：**砂漠** — 大きな砂丘のアップダウン、砂丘越えジャンプ
- ステージ3：**荒野＋砂漠の境目** — メサ（台地）を越えてゴールの町へ
- 地形は Unity Terrain、コースはチェックポイントで順位と逆走を判定

## 6. ビルダーに任せること
- 各数値（速度・加速・スタミナ・クールダウン・ポイント配分）の初期値と調整
- コースの具体的なレイアウト、チェックポイント配置、遺物の配置（生成ツールのパラメータとして調整可能にする）
- 使用する無料/有料アセットの選定（トゥーン調で統一すること）
- 同期方式の細部（送信頻度・補間方法）。ただし「他者の馬がガクつかない」ことは必須
- UI（順位・スタミナ・能力クールダウン表示）のデザイン
